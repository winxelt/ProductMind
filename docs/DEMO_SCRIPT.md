## 7:15–8:15 · Как устроен ProductMind

**Диктор**

> Содержательный анализ выполняет Codex в открытой папке VS Code. Для нового разбора нужна доступная сессия Codex. Python отвечает за чтение материалов. Для текстового PDF он сохраняет номер страницы, для таблицы Excel — лист и строку. Можно также импортировать документ Word, CSV или обычный текст. Отдельная база SQLite в папке проекта хранит извлечённые фрагменты, источники и полные версии решений. При сохранении проверяются исходная версия и номера источников. На экране штатные тесты. Они проверяют чтение файлов и работу журнала. Смысл вывода и его соответствие источнику агент сверяет по чек-листу.

**В кадре.** Откройте `docs/ARCHITECTURE.md` → схему; при отсутствии рендера Mermaid покажите две строки таблицы «Что запоминает проект». В 7:42 выполните `.\run.cmd test`. Затем откройте `evaluations/quality-checklist.md` → «Варианты и возражения».

**Ожидаемый результат.** При успешном прогоне в терминале видны `Ran 7 tests` и `OK`. Схема отделяет Codex от CLI. Самостоятельного вызова LLM API в Python нет.

### Подготовка терминала до записи

```powershell
$OutputEncoding = [Console]::OutputEncoding = [Text.UTF8Encoding]::new($false)
$v = 'projects/youth-retention-v11'
$p = Join-Path $env:TEMP ('pm-video-' + [guid]::NewGuid().ToString('N'))
New-Item -ItemType Directory -Path $p | Out-Null
Copy-Item "$v/journal.sqlite3" $p
$c = .\run.cmd --project "$p" context | Out-String | ConvertFrom-Json
$c | Select-Object base
$c.sources_are_untrusted_data | Format-Table id,path -AutoSize
```

Проверьте `base = 2` и три строки источников. Путь к временному каталогу можно получить командой `$p`. Подмените им маркер в запросе второго чата **до записи**, скройте личную часть пути в кадре. Если перезапустили терминал, повторите подготовку.
