# ProductMind

Мобильный оператор видит возможное снижение активности и предлагает игровые бонусы. Что проверить, прежде чем тратить деньги на подписку? ProductMind помогает команде сформулировать проблему, сравнить развитие, сохранение и закрытие направления, а затем пересмотреть выбор по новым данным. В поставке есть [разбор этого кейса](projects/youth-retention/REPORT.md) и [протокол его проверки](projects/youth-retention/TESTING.md).

**Strategic Decision Engine v1.1** задаёт правила разбора в сессии Codex. В каждом новом решении агент отличает симптом от причины, задаёт до пяти вопросов с последствиями для выбора и сравнивает три направления по общей матрице. У рекомендации есть уровень уверенности, условия пересмотра и ближайшая проверка. При неполном брифе агент сохраняет предварительный вывод. [Пример с нерешённым противоречием](projects/youth-retention-v11/REPORT.md) · [Проверка совместимости](projects/youth-retention-v11/TESTING.md)

## Как устроена работа

**Проверено участие руководителя.** В учебной копии официального кейса Codex открыл две страницы операторов и зарегистрировал карточки доказательств через CLI. После представления вариантов человек запросил дополнительные данные. Его дословный ответ стал отдельным источником, а решение восстановлено из версии 2 через context и history. Веб-доступ предоставляет сессия Codex. [Протокол и границы проверки](projects/megafon-official-hitl/HITL_TESTING.md)

**Codex** в открытой папке VS Code ведёт содержательный разбор по [рабочей инструкции](instructions/codex-run.md). **Python CLI** извлекает документы с координатами фрагментов. **SQLite** хранит источники и версии решения в папке каждого проекта. Самостоятельный вызов LLM API в CLI отсутствует. Для нового анализа нужна доступная сессия Codex. Чтение готового журнала и воспроизведение демо выполняются локально. [Схема и устройство памяти](docs/ARCHITECTURE.md)

Отчёт связывает факты с источниками, отдельно фиксирует допущения, гипотезы, прогнозы и открытые вопросы. Для трёх альтернатив Codex оценивает пользу, риски, затраты и способы проверки. Рекомендация включает возражения, продуктовую и коммуникационную стратегии, план проверки и условия пересмотра.

## Установка на Windows

Распакуйте ZIP в отдельную папку, откройте её в VS Code и запустите PowerShell в корне. Для воспроизведения используйте Python 3.12 и виртуальное окружение. Команды установки рассчитаны на Windows с Python Launcher и доступом к репозиторию Python-пакетов.

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Если Python 3.12 доступен как `python`, первую команду можно выполнить как `python -m venv .venv`. Активация окружения не требуется. `run.cmd` ищет рабочий Python в .venv, затем в комплекте Codex, затем в PATH. Четыре прямые зависимости закреплены в [requirements.txt](requirements.txt). SQLite входит в Python. В архиве нет виртуального окружения и установленных библиотек.

## Запуск и демонстрация

```powershell
.\run.cmd test
.\run.cmd demo
.\run.cmd --project projects/youth-retention context
.\run.cmd --project projects/youth-retention/recovery-test history
```

- **test** запускает семь тестов импорта и сохранения. Успешный вывод заканчивается строкой `OK`.
- **demo** создаёт отдельный временный журнал и воспроизводит два заранее подготовленных решения по синтетическому кейсу студенческого клуба. Путь к журналу выводится в терминал.
- **context** читает бриф, координаты и последнее решение по учебному кейсу оператора. Основной журнал youth-retention содержит версию 1.
- **history** в recovery-test показывает обе версии отдельного технического сценария. Синтетическое условие об отсутствии возрастного среза меняет следующий шаг. Наблюдения об абонентах в этом сценарии отсутствуют.

Для живого разбора откройте Codex и укажите бриф и отдельную папку проекта. Например, «Выполни instructions/codex-run.md для моего брифа. Импортируй его в projects/my-project, проверь цель, сравни варианты и сохрани решение с источниками». Для продолжения укажите ту же папку и новый материал. Перед сохранением Codex читает актуальную версию через context. [Сценарий защиты с командами](docs/DEMO_SCRIPT.md)

## Форматы и ограничения

| Вход | Что попадёт в журнал |
| --- | --- |
| PDF | Текст с номером страницы. Для сканов требуется предварительное распознавание |
| DOCX | Абзацы и строки основных таблиц. Изображения, колонтитулы и вложенные таблицы выходят за пределы импорта |
| XLSX, XLSM | Листы и строки, включая формулы как текст. Расчёт формул и выполнение макросов отсутствуют |
| XLS | Сохранённые значения и даты через xlrd |
| CSV, TXT, Markdown | Строки с координатами. CSV поддерживает запятую, точку с запятой и табуляцию. Кодировки UTF-8, UTF-16 с меткой и Windows-1251 |

Команда context выгружает весь извлечённый текст. Для больших документов агенту приходится отбирать нужные фрагменты. CLI проверяет ID источников и базовую версию решения. Соответствие вывода цитате и актуальность Markdown-сводок проверяет Codex. Родительские каталоги внешних материалов могут сохраняться в личном журнале. В четырёх журналах поставки пути даны от корня проекта.
