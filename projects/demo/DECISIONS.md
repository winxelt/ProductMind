# Журнал решений

Подробный журнал демонстрационного проекта. Записей нет: продуктовых решений ещё не принимали.

Журнал дополняет `STATE.md`. В файле состояния остаётся краткое принятое решение и отклонённые варианты. Здесь хранится полная запись. Формулировки в двух файлах должны совпадать. Старую запись не удаляют при пересмотре: добавляют новую и ссылаются на предыдущую.

Для стратегического решения в поле «Альтернативы» обязательно есть сохранение текущего положения, хотя бы один путь изменения и закрытие направления. Так журнал соблюдает `AGENTS.md`.

## Поля

| Поле | Что писать |
| --- | --- |
| Дата | Дата записи. Не ставь дату задним числом без пометки |
| Решение | Что именно решили. До проверки пометь, что это рабочая гипотеза, если проверка ещё не прошла |
| Основания | Факты и гипотезы со ссылкой на ID источника или на ответ пользователя. Без основания решение не записывают |
| Альтернативы | Какие варианты рассмотрели и почему не выбрали их |
| Ответственный | Кто отвечает за решение и за следующий шаг. Если человек не назван, напиши «не назначен» |
| Показатели контроля | По каким показателям следят, что решение ещё держится. Если показателя нет, напиши «не заданы» |
| Условие пересмотра | Какой новый факт, смена цели или результат проверки заставит открыть решение снова |
